## 2. 詳細

### 2.1 マウスの戻る・進むボタン
- **結果：原因は Logicool Options+ のジェスチャー機能。普通のゲーミングマウスでは効いた。プロジェクト側の変更なし（2026-11-11 ユーザー確認）**
- まず原因を調べる。候補：キー設定画面が押されたキーをどう受け取って保存しているか（`OnMouseButtonDown` で拾えているか、キー名が `ThumbMouseButton` / `ThumbMouseButton2` で保存されているか）、保存したキー名から IMC を作るときに対応が抜けていないか、実行時の IMC の作り直しが反映されているか
- 直したら、戻る・進むをどれか 1 つの操作（例：スキル1）に割り当てて、PIE でその操作が動くこと、保存して読み直しても残ることを確かめる
- 他のマウスボタン（中ボタン、ホイール上下）が同じ理由で効かないなら一緒に直す

### 2.3 スモーク（サイファーのケージ方式）
- 置き方は今のまま（Q で構え、左クリックでアンカーを投げる）
- **展開**：構えていなくても、画面中央から 6° 以内に未発動の自分のアンカーがあれば、インタラクト（初期 F、`IA_Interact`）で展開する。距離・壁越しは問わない
  - 照準内にアンカーがあるときは、武器を拾うより展開を優先する。アンカーが無ければ今どおり武器を拾う
  - 複数あれば画面中央に一番近いもの
- 構え中の左クリックでアンカーを展開する今の動作は外す（左クリックは投げるだけ）。同じキーをもう一度押して展開する動作があれば外す
- 未発動のアンカーの画面上の印は、**構えていなくても常に**出す。照準が 6° 以内に入っている印は色を変え、画面下中央に「F：スモーク展開」を出す（キー名は実際の割り当てを表示できればそれ、難しければ F 固定でよい）

### 2.4 リコール（経路をたどる）
- 目印を置いた時点から、プレイヤーの位置を記録する。前回記録から 25cm 以上動いたら 1 点追加。上限 2000 点。超えたら一番古い点を捨てる（目印の位置は別に持っているので、最後は必ず目印へ着く）
- 2 回目の E：
  - 無敵（`TakeWeaponDamage` の先頭で弾く。チートと同じ場所に `bRecalling` の判定を足す）
  - 移動・視点・射撃・スキル・インタラクトの入力を受け付けない（視点は動かしてもよいなら動かしてよい。最低限、移動と射撃とスキルを止める）
  - 記録した点を新しい順にたどり、最後に目印の位置へ着く。速さは通常の走る速さ（`CharacterMovement` の歩行の最大速度。しゃがみや歩きの速度ではない）。毎フレーム、次の点へ向けて `速さ × DeltaTime` だけ進める（`SetActorLocation`、Sweep なし。重力で落ちないよう移動モードを Flying にするか、移動を止めて位置だけ動かす）
  - 着いたら移動モード・入力・無敵を元に戻し、目印を消す。0.4 秒の無防備時間は廃止
- 死亡・ラウンド終了で、記録と目印を消し、状態を戻す
- 設置中・解除中に戻るとき、設置・解除は中断する（今のスキル使用時の中断と同じ）

### 2.5 リコン
- 初速を約 2 倍にする（2000 → 4000 前後）。重力が強すぎて伸びない場合は、投げる角度を少し上げてよい。届く距離が今の約 2 倍になったことを数値で確かめる

### 2.6 ヒール
- E で開始。体力が最大になるまで 1 秒に 10 ずつ回復する（0.1 秒ごとに 1、など）。アーマーは回復しない
- 開始時に回数を 1 減らす。回復中にもう一度 E を押しても何もしない（回数を減らさない）
- 最大に達したら止まる。死亡・ラウンド終了で止まる。撃たれても回復は続ける
- 使える条件は今と同じ（体力が最大でない、フェーズ 1・2）

### 2.7 フラッシュ
- **自分**：炸裂時、次をすべて満たせば画面を白くする
  - プレイヤーのカメラの前方と、カメラ→炸裂点の方向の内積 > 0.5
  - 距離 5000cm 未満
  - カメラから炸裂点へのトレース（Visibility）が遮られない。煙にも遮られない
- 画面の白：最初の 2 秒は真っ白（不透明度 1）、残り 3 秒で 0 まで薄くする（合計 5 秒、敵と同じ）。`WBP_GameHUD` に全画面の白い Image を足すか、`BP_PR_HUD` で全画面の白い矩形を描く。HUD や照準より手前に出す
- 死亡したら白を消す
- **食らった Bot の見た目**：`BlindUntil` が未来の Bot について、プレイヤーから見えている（画面内・遮られない）ときは、頭の上に目印を出す。例：黄色い星（✶ や * の文字）が頭の周りを回る、または白い光る輪。`BP_PR_HUD` で描くのが簡単。Bot 自体の色を変えられるなら併用してよい

### 2.8 アラームボット
- 検知時（今の「同じ Bot には 10 秒に 1 回まで」の条件はそのまま）：
  - その Bot を **7 秒間鈍足**：`CharacterMovement` の最大速度を 50%（仮）にする。終了時に元に戻す。すでに鈍足中なら終了時刻を延ばす。元の速度は Bot の状態（歩き・走り）で変わる可能性があるので、鈍足の掛け方は Bot の速度を決めている箇所に倍率を掛ける形にする
  - **音**：既存の効果音から目立つもの（ビープ等）をプレイヤーの位置で鳴らす（2D）
  - **画面通知**：今の `NoticeText`「アラームボットが敵を検知」に加え、画面の中央上寄りに大きめの橙色の表示を 1 秒点滅させる程度でよい
  - 表示（`RevealUntil`）も 7 秒にする
- 鈍足の Bot は頭の上に小さな目印（青など）を出してよい（任意）

### 2.9 チート
- U でオン・オフ（今のまま）。オンの間は次をすべて行う
  - 無敵（今のまま）
  - **タイマー停止**：購入フェーズ・戦闘・設置後（スパイク）のすべての残り時間が減らない。オフに戻したら、止まっていた値から再開する
  - **弾無限**：撃っても弾倉の弾が減らない（リロード不要）。予備弾も減らない
  - **スキル無限**：選んでいる 3 スキルを、残り回数に関係なく使える。使っても回数が減らない。オンにした時点で残り回数を最大にして HUD もそれを表示する（オフにしたら最大のまま残してよい）
- 設定画面の表示名を「チート」に、HUD の表示を「チート：無敵・時間停止・弾無限・スキル無限」に変える

### 2.10 フラッシュ・アラームボットの構え
- フラッシュ（C）・アラームボット（Q）も、リコン・スモークと同じ「スキルキーで構え → 構え中の左クリックで投げる・置く」方式にする。`SkillMode` は 2＝フラッシュ構え、4＝アラームボット構え（1 リコン、3 スモークと重ならない）
- 構えの解除（同じキー再押し、武器の持ち替え、死亡）、画面下の案内（「左クリック：投げる」「左クリック：置く」）、スキル枠の黄色はリコン・スモークと同じ扱い。投げる・置く処理（`ThrowFlash`、`AlarmPlace`）と回数の減り方（発動時に減る）、チートのスキル無限は変えない

### 2.11 スモークの中を空洞にする
- 煙は殻（球の表面）だけにして、中は見通せる（サイファーのケージと同じ）。画面全体を灰色で塗る処理（`BP_PR_HUD.DrawSmokeCover`）をやめる。球は両面表示のままなので、中に入ると内側の壁が見え、殻の内側の通路・床・人物は見える
- 視線の判定（`BFL_PR.IsSmokeBlocked`）は「殻を横切るときだけ遮る」。各煙について、Start と End がどちらも球の内側（中心から 450cm 未満）ならその煙では遮らない。片方だけ内側なら遮る。どちらも外側なら、従来どおり線分上の最近点が 450 未満なら遮る
- これで、同じ煙の中にいる Bot とプレイヤーは互いに見え、中から外・外から中・煙をはさんだ外から外は見えない。呼び出し側は変えない

## 3. 確認
各項目、PIE でログか画面で確かめ、§4 に結果を書く。特に：
- 2.1：戻る・進むを割り当てた操作が動く
- 2.3：構えずに F でアンカーが展開する。アンカー無しの F で武器を拾える
- 2.4：曲がった経路で目印を置き、離れてから戻る。戻りの途中の位置ログが経路に沿う。戻る間に撃たれても体力が減らない。所要時間 ≒ 経路長 ÷ 走る速さ
- 2.6：体力 50 から 10 秒前後で 150（またはその難易度の最大）に戻る
- 2.7：炸裂点を見て白くなる、背を向けて白くならない。食らった Bot の頭上に目印
- 2.8：鈍足の速度ログ（前後の最大速度）、音、通知
- 2.9：オンで時間・弾・スキル回数が減らない

## 4. 実装結果

### 24-A（2026-11-11）
担当：§2.1、§2.2、§2.3、§2.5、§2.6、§2.9（§2.4・§2.7・§2.8 は別担当）。

#### 2.1 マウスの戻る・進むボタン
- 原因：**特定できなかった**。コードの欠陥は見つからなかった。
  - キー設定の受け取り（`WBP_KeyBindRow` の `InputKeySelector`）：エンジンのソース（`SInputKeySelector::OnPreviewMouseButtonDown`）は押されたマウスボタンをそのまま `GetEffectingButton()` で受け取り、`ThumbMouseButton` / `ThumbMouseButton2` も同じ経路。Windows 側（`WindowsApplication.cpp` の `WM_XBUTTONDOWN`）から Slate までの変換にも除外はない
  - 保存・IMC への反映：`SetBind` → `SaveBinds` → `ApplyBinds` → `BuildIMC`（`MapKey`）はキーの種類に依存しない
  - 実動作（PIE）：`GameInstance.SetBind(Skill1, ThumbMouseButton)` ＋ `PlayerController.ApplyBinds` のあと、`simulate_input` の `key_tap ThumbMouseButton` で `SkillMode` が 1 になり、スキル1（リコン構え）が動いた（`G` に割り当てた場合も同様）。保存ファイル（`PR_Settings2.sav`）に `ThumbMouseButton` の文字列が書かれることも確認
- 未確認：実機の戻る・進むボタンでの割り当て操作（このセッションでは画面操作の許可が下りず、物理ボタンを送れなかった。PowerShell から `XBUTTON1` を送ったが PIE ビューポートに届かず無効）。有力な原因は環境側：この PC には Logi Options+ / ELECOM Mouse Assistant が入っており、これらのドライバは戻る・進むを XBUTTON ではなく「ブラウザの戻る・進む」やキー入力に置き換えることがある（その場合はエンジンに `ThumbMouseButton` が届かない）。ドライバのボタン設定を「標準（戻る・進む）」にするか、アプリ別設定で UE を除外して再確認してほしい
- 後始末：試験で書き換えたキー設定は `ResetBinds` で初期値に戻した。スキル選択（`PR_Skills`）は元の `[2,1,1]` に戻した

#### 2.2 最大回数
- `DT_Skills`：`0_0` ブリンク、`0_2` リコンの `MaxCharges` を 1 → 2。フラッシュ（`0_1`）は最初から 2 で、買えない原因はなかった（コードは `DT_Skills` の `MaxCharges` を `SkillInfo` で読むだけ）。購入画面の「n/最大」と HUD の ●○ は `SkillInfo` の最大値で作られるので 2 枠になる。ヒール（`1_1`）とスモーク（`2_0`）の説明文も新しい仕様に合わせて更新
- 確認：データテーブルの値のみ。購入画面と HUD の実画面での枠の数は目視していない

#### 2.3 スモーク
- `BP_PR_Character`：変数 `AimBest`（Actor）、`AimBestDot`（float）。関数 `AnchorAimed`（画面中央から 6°以内〔内積 ≥ 0.9945〕で一番中央に近い未発動アンカーを返す。無ければ None）、`SmokeDeploy`（`AnchorAimed` のアンカーの位置に `BP_PR_SmokeField` を出してアンカーを消し、`Used` を返す）。`IA_Interact` の Started は `SmokeDeploy` を呼び、`Used` が false のときだけ今までどおり `PickupNearby`。`SmokeFire`（構え中の左クリック）は、アンカー展開のループを外して「投げるだけ」にした（同じキーの再押しで展開する動作は元から無い）
- `BP_PR_HUD`：変数 `bAimedAnchor`。`DrawAnchors` の `SkillMode`==3 の条件を外し、未発動アンカーに常に白い四角を出す。照準が 6°以内のものは黄色の枠（22px）を重ね、`bAimedAnchor` が true のとき画面下（高さ − 200px、中央）に「[Interactの割り当てキー]：スモーク展開」を黄色で出す（キー名は `GameInstance.GetBind("Interact")` の表示名）
- 確認（PIE）：スモークを選び、アンカーを 1 個投げた（`SkillMode` は 0＝構えなし）。照準がアンカーから外れているとき F を押すと `PickupNearby` が走り（ログポイント runs=1）、煙は出ない。コントロール回転を下に 8° 向けて照準にアンカーを入れて F を押すと `BP_PR_SmokeField`（スケール 9）がアンカーの位置に出て、`PickupNearby` は走らなかった
- 未確認：HUD の印（白／黄色の枠）と下部の文字の実画面での見た目、複数アンカーのうち一番中央に近いものを選ぶこと（比較ロジックはグラフのみ）、壁越しの展開

#### 2.5 リコン
- `BP_PR_SkillRecon.Move`：`InitialSpeed` 2000 → 4000、`MaxSpeed` 2200 → 4400（投げる角度は変えていない）
- 確認（PIE、(-3600, 0) から水平に投げる）：変更前は x=-2424 に停止（距離 1176cm）、変更後は x=-1317 に停止（距離 2283cm）＝約 1.94 倍。落下時間が同じで水平の速さが 2 倍になるため、ほぼ 2 倍になる

#### 2.6 ヒール
- `BP_PR_Character`：変数 `bHealing`、カスタムイベント `HealLoopEvt`（0.1 秒待つ → 生きている・`bHealing`・体力 < `PlayerMaxHealth`・フェーズ 1 か 2 のとき `Health` を 1 増やして自分を呼ぶ。条件を外れたら `bHealing` を false にする）。`HealUse` は `bHealing` を true にして `HealLoopEvt` を呼ぶだけに変更（古い即時回復のノードは接続を外して残してある）。`SkillSpecialPress` の「ヒールが使えない」判定に `bHealing`（回復中）を OR で追加＝回復中の再押しは回数を減らさない
- 確認（PIE、イージー＝最大 300）：体力 50 で E → 約 2.4 秒後に 74、約 10 秒後に 189、その後 262、そのあと 300 で止まった（10/秒前後）。回復中にもう一度 E を押しても回数は変わらなかった（2 → 1 のまま）
- 未確認：死亡・ラウンド終了での停止（`bDead` とフェーズの条件を入れたがグラフのみ）、撃たれても回復が続くこと（`TakeWeaponDamage` に触っていないので続くはず）、アーマーが増えないこと

#### 2.9 チート
- `BP_PR_GameMode`：変数 `CheatLastT`。`MatchTick`（0.1 秒ごとの呼び出し）の先頭で `bCheat` のとき、`CheatFill`（`SkillSel` の 3 スキルについて `SkillCharges` を `SkillInfo` の `MaxCharges` にそろえる新関数）を呼び、フェーズ 0〜2 では `PhaseEndTime` に「前回の `MatchTick` からの経過時間（上限 0.5 秒）」を足して残り時間を止める。最後に `CheatLastT` を今の時刻にする。購入・戦闘・設置後（スパイク）はすべて `PhaseEndTime` で数えているので 1 か所で止まる。オフに戻すと止まった値から再開
- `BP_PR_WeaponBase.Fire`：`Set Ammo` の前に「`bCheat` かつ `GetOwner` がプレイヤー」で分岐し、成立時は弾を減らさない（Bot の武器は従来どおり減る）
- `DT_KeyBinds` の `Cheat` の表示名を「チート」に、`WBP_GameHUD.CheatText` を「チート：無敵・時間停止・弾無限・スキル無限」に変更
- 確認（PIE）：U でオン。購入フェーズ（15 秒）で、ゲーム時間 15.87 → 44.69（約 29 秒）のあいだ `PhaseEndTime − 時間` は 15.82 → 15.81 で一定のままフェーズ 0 が終わらなかった。`SkillCharges` がオンで `[2,1,2]`（選択中の 3 スキルの最大）になった。ピストルで発射すると `Fire` の分岐が True（チート・プレイヤー所有）で `Ammo` は 12 のまま
- 気づいた点：初めに `GetWorldDeltaSeconds` を足す作りにしたところ、`MatchTick` が毎フレームではなく 0.1 秒ごとなので残り時間が止まらず（約 0.85 倍で減った）、上の「前回呼び出しからの経過時間」に直した
